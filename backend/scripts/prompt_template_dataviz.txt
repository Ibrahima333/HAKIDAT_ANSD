## COLOR PALETTE SWITCHER (MANDATORY — except Map, Filled map, Waterfall, Gauge, Card, Multi-row card)

Every chart you build — EXCEPT the six types listed above — MUST let the user
switch between 4 curated color palettes via a native Plotly **dropdown**
menu, computed in Python and wired through `fig.update_layout(updatemenus=...)`
with `method="restyle"`. No custom JavaScript, no HTML post-processing — this
runs entirely through Plotly's own menu mechanism, exactly like the map
style switcher.

Use `type="dropdown"`, never `type="buttons"` — four separate button pills
spread across the top of the chart collide with the title and, on shorter
containers, with the plot itself. A dropdown is a single compact control.
You MUST also reserve real margin for it via `fig.update_layout(margin=dict(t=70))`
— `y` values above 1 place the menu outside the plot's normal paper area,
and without an explicit top margin it can render on top of the chart instead
of above it.

**Maps already have their own Standard/Sombre/Satellite switcher (see STRICT
MAP RULE) — do not add a color switcher there.** Waterfall's colors are
semantic (increasing/decreasing/total) and Gauge/Card/Multi-row card show
numbers, not categorical data — none of these get a palette switcher.

### The four palettes (use exactly these hex values)

```python
PALETTES = {
    "Ambre":    ["#C8940A", "#E0B44A", "#8A6205", "#F2CD7A", "#5C4103", "#F9E3B0"],
    "Océan":    ["#2563EB", "#60A5FA", "#1E3A8A", "#93C5FD", "#1E40AF", "#BFDBFE"],
    "Émeraude": ["#059669", "#34D399", "#065F46", "#6EE7B7", "#047857", "#A7F3D0"],
    "Violet":   ["#7C3AED", "#A78BFA", "#4C1D95", "#C4B5FD", "#5B21B6", "#DDD6FE"],
}
```

**Initial colors:** pass `color_discrete_sequence=PALETTES["Ambre"]` directly
to your `px.bar`/`px.line`/`px.area`/`px.scatter`/`px.pie`/`px.funnel`/`px.treemap`
call. This is a native Plotly Express parameter — it works whether the chart
ends up with one trace or many, so the chart opens already on-brand without
any extra logic.

### Two cases for the switcher itself — copy the block matching your chart

**Case A — Bar, Column, Line, Area, Scatter, Funnel** (anything using
`marker.color` or `line.color`). Do NOT try to determine yourself whether
your chart has one trace or several — `px.bar(...)` with no `color=` still
produces one trace with many points, while `color="region"` produces one
trace per region, and the `restyle` array-nesting differs between the two.
The snippet below detects it from `fig.data` at runtime, so it is correct
either way without you having to reason about it:

```python
color_attr = "marker.color"  # ou "line.color" pour un Line/Area chart
n_traces = len(fig.data)

if n_traces == 1:
    # Une seule trace : la couleur varie par barre/point, pas par trace.
    tr = fig.data[0]
    n_points = len(tr.x if tr.x is not None else tr.y)
    def restyle_args(colors):
        return [{color_attr: [[colors[i % len(colors)] for i in range(n_points)]]}, [0]]
else:
    # Plusieurs traces (color= utilise) : une couleur par trace.
    trace_indices = list(range(n_traces))
    def restyle_args(colors):
        return [{color_attr: [colors[i % len(colors)] for i in range(n_traces)]}, trace_indices]

fig.update_layout(
    margin=dict(t=70),
    updatemenus=list(fig.layout.updatemenus or []) + [dict(
        type="dropdown", direction="down", showactive=True, active=0,
        x=1.0, xanchor="right", y=1.0, yanchor="bottom",
        pad=dict(r=5, t=5, b=5),
        buttons=[
            dict(label=name, method="restyle", args=restyle_args(colors))
            for name, colors in PALETTES.items()
        ],
    )]
)
```

**Case B — Pie, Donut, Treemap**: single trace, one color per slice/category.
The attribute is `marker.colors` (plural, note the "s"), not `marker.color`.
Also set `textposition="inside"` — with more than a handful of slices,
Plotly's default outside labels with leader lines overlap and become
unreadable (see example below); inside labels stay anchored to their slice.

```python
n_slices = len(fig.data[0].labels)
fig.update_traces(textposition="inside", textinfo="percent")

fig.update_layout(
    margin=dict(t=70),
    updatemenus=list(fig.layout.updatemenus or []) + [dict(
        type="dropdown", direction="down", showactive=True, active=0,
        x=1.0, xanchor="right", y=1.0, yanchor="bottom",
        pad=dict(r=5, t=5, b=5),
        buttons=[
            dict(
                label=name,
                method="restyle",
                args=[{"marker.colors": [[colors[i % len(colors)] for i in range(n_slices)]]}],
            )
            for name, colors in PALETTES.items()
        ],
    )]
)
```

* Use the exact hex values above — do not alter, lighten, or invent new ones.

## DATE / TIME CONVERSION (STRICT — PREVENTS CRASHES)

A numeric column MUST NOT be assumed to be a Unix timestamp just because the
column name or the business question suggests a time dimension. Wrongly
guessing the unit (`s` vs `ms`) or converting a non-timestamp numeric column
(e.g. an ID or a code) crashes the script with `OutOfBoundsDatetime` /
`OverflowError`, and the user loses the chart entirely.

* NEVER call `pd.to_datetime(col, unit="s")` or `unit="ms"` unless you have
  checked, from the Data Preview above, that the values plausibly fall in a
  real epoch range:
  * seconds since epoch (years ~1970–2100) → roughly 10 digits (0 to ~4.1e9)
  * milliseconds since epoch → roughly 13 digits (0 to ~4.1e12)
  * a value with 14+ digits is NOT a plausible epoch timestamp — treat the
    column as categorical/numeric instead, do NOT convert it to a date.
* If the column already looks like a date string (e.g. `2025-07-11`,
  `20250711`), use `pd.to_datetime(col, errors="coerce")` WITHOUT forcing a
  `unit=` — let pandas infer the format.
* ALWAYS wrap any `pd.to_datetime(...)` call in `try/except`. On failure,
  fall back to using the column as-is (categorical or numeric axis) instead
  of letting the exception propagate and crash the whole script.
* When genuinely unsure whether a column is temporal, DO NOT guess — treat
  it as categorical/ordinal and pick a non-time-based chart type instead.
